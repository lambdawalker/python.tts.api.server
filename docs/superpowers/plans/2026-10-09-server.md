# Shared TTS Server Implementation Plan

> Execute inline using superpowers:executing-plans, with contract tests before implementation.

**Goal:** Implement the shared server defined in design.ai/tts and interoperate with python.tts.api.client.

**Architecture:** Engine-independent FastAPI and optional MCP interfaces call the same application service. SQLite stores voices, asset metadata, jobs, events and idempotency records; a single background worker owns adapter execution. Engine repositories supply adapters. A clearly labeled fake adapter demonstrates the contract without model dependencies.

**Tech stack:** Python >=3.10, Pydantic 2, FastAPI, SQLite, SoundFile, MCP SDK 1.x, uv, pytest.

**Spec:** https://github.com/lambdawalker/design.ai/tree/main/tts

## Global constraints

Preserve caller text/instructions/transcripts. Reject unknown request fields and unsupported controls. No automatic inference retries. HTTP/MCP share validation and authorization. Client disconnects do not cancel jobs. No Torch/CUDA dependency in this package. One process/worker per data directory, enforced by a lock. Queued/running jobs fail with server_restarted after restart. MCP is optional. No GPU validation claims.

## Review focus

- Retry after changing defaults or deleting voices must return the original job.
- Cancellation racing completion must not claim a still-running adapter has stopped.
- Cross-caller references, jobs and audio must remain inaccessible through both transports.
- Retention must protect active job references and expose expired assets/history explicitly.
- Invalid audio, oversized multipart bodies and adapter failures must yield bounded, structured outcomes.

## Tasks

1. Contracts and adapter boundary: `models.py`, `errors.py`, `adapter.py`, `fake.py`, `tests/test_contracts.py`. Strict schemas, exact profile metadata, native validation and deterministic WAV output. Write and run failing tests, implement, verify.
2. Persistent services: `store.py`, `assets.py`, `service.py`, `tests/test_service.py`. Atomic submissions/events, durable voice snapshots, worker execution, restart/cancellation/idempotency/retention, reference ownership. Write and run failing lifecycle tests, implement, verify.
3. Transports: `http.py`, `mcp.py`, `auth.py`, `cli.py`, `tests/test_http.py`, `tests/test_mcp.py`. All specified routes/tools, ETags, error normalization, bounded uploads, SSE replay/heartbeats. Run HTTP and MCP parity tests.
4. Integration and delivery: SDK loopback tests, generated OpenAPI/request schemas, CI, README, adapter/deployment docs and design.ai source links. Test sync/async existing client without modifying its behavior, lint, build wheel/sdist, inspect artifacts. Review whole branch before publishing changes.

## Decisions

The user's follow-up authorizes implementation of the already reviewed central design. This plan makes deployment choices concrete without another approval round. Bearer tokens map to caller IDs; absent tokens mean explicit loopback-only development mode in the CLI. WAV/FLAC are initial validated input containers; adapters advertise their own output encodings. SQLite metadata remains as tombstones; bounded event history and expiring binary assets have configurable retention.
